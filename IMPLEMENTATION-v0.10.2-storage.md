# Folio 0.10.2 voice storage

The Voice packs sheet has an explicit storage section: model bytes, transfer bytes, previews/generated audio and currently reclaimable bytes. Details distinguish current models, manifest-owned old models, rollback, transfer metadata, downloads and unknown paths. Refresh is explicit or triggered by pack phase changes, not every download-progress tick. User confirmations separately remove old versions or discard selected partial downloads; cancellation is available. Generated audio and recorded samples are measured separately and kept here; existing Storage and backup owns generated-audio clearing.

Ownership is recorded only after successful verified adoption or verified archive activation. noBackupFilesDir/voice-storage-owned.json stores pack/version, signed archive identity, file names/sizes/hashes and component references. It is bounded, atomic and read back after writing. Current catalog versions are always protected. Unknown/corrupt ownership cannot authorize deletion. Old model roots containing unrecognized files/directories are kept. Shared references are followed transitively; rollback markers conservatively protect associated model versions too. No directory-name prefixes or guessed versions authorize deletion.

Historical app source ZIPs0.3/0.4/0.5/0.6/0.7/0.9/0.10.1 were inspected locally: Kokoro still uses kokoro-v1_0-fp32-sherpa1.13.8; Supertonic still uses supertonic3-int8-20260511-cca5a0e6-sherpa1.13.8-steps8-seed42; current Pico is pico-int8-r100k-40060c99-kanade961f20bf-hift-v1. These are CURRENT options, not obsolete because an app version changed. Their existing verified copies are adopted into ownership tracking. No invented legacy directory IDs are deleted; unfamiliar test/legacy folders remain reported. Old-version cleanup may correctly recover zero bytes on existing installations. Private ownership records enable safe superseded-version cleanup after future model changes.

VoiceModelUse leases are acquired before file preparation and held until queued native release completes. Kokoro/Supertonic include the narrow lifecycle hook; root wires Pico, including its direct benchmark path. Leases and cleanup reservations use canonical noBackupFilesDir namespaces; a racing acquisition of a selected cleanup path is rejected. Native inference/destruction keeps its existing serial worker. SpeechController active-book/preparation/preview guards remain. Models still current, loaded, shared or required for rollback are never old-cleanup candidates. Explicit Remove pack also checks leases/shared users and includes that pack's known safe old versions; it keeps rollback and unknown transfer entries.

Download ownership uses exact catalog/record identities in transfer metadata or an app-created owner marker, not the pack-folder name alone. Discard first enters a maintenance state that blocks stale worker updates/re-enqueue, awaits WorkManager cancellation, then acquires the worker's transfer mutex (the same lock held through HTTP/file close). The storage operation lock, native queue barrier, fresh inventory, model reservations and per-file canonical/no-symlink checks precede deletion. Other active pack transfers defer a selected transfer cleanup instead of being cancelled implicitly. Cancel/drain waiting is bounded; cancelling before deletion keeps files. Interrupted deletion can recover only part of the advertised bytes; a fresh inventory shows the rest. New candidates are never silently added to a confirmed selection. Rollback `previous` and unknown transfer entries are retained.

Cleanup traversal stays inside noBackupFilesDir/local-voices or voice-transfers, rejects symlinks/reparse escapes and bounds depth/file count. It never enumerates/removes library metadata, annotations, book files, speech/guided checkpoints, workspace conversion artifacts or APK-native shared libraries. Samples/audio cache paths are read for totals only. Sizes are measured on refresh; unreadable/linked paths are protected with size unavailable rather than followed. The ownership registry retains64 version records; older unrecorded roots become unknown/kept. Excessively large/unrecognized trees are also kept.

Focused JVM tests cover owned-only old deletion, current/unknown/cache/bookmark preservation, transitive sharing and rollback, a model becoming loaded while native drain waits, cancelled-worker critical-section drain before file deletion, explicit removal versus standalone engine leases, cancellation releasing maintenance, corrupt registry/unrecognized files, reference-counted/root-isolated leases and symlink escape. The symlink case is skipped where the host cannot create links. Android tests exercise private filesystem cleanup/leases and verify the voice-pack storage UI. No Gradle, ADB or physical benchmark was run by the delegate; root owns combined build/test/device evidence. Physical-device storage totals are not claimed until measured.
